## FIG: Tenant Isolation Architecture

FIG: Architecture diagram, "Tenant Isolation: One Process, Two Tenants, Zero Leakage." Three horizontal lanes. Top lane labeled **Tenant harbor (momentum desk)**, bottom lane labeled **Tenant beacon (dividend desk)**, middle lane labeled **Shared agent process (untrusted by both)**. Left side: each tenant lane holds a "Session token (HMAC-signed: tenant_id, scopes, expiry)" box; a solid arrow from each token box points right into a gate in the middle lane labeled "**require_tenant**: verify signature + expiry + revocation + scope — on EVERY call." From the gate, three arrows fan out to three partitioned stores drawn as divided boxes: **Namespace (tenant_id, key)**, **Write-ahead ledger (tenant column, queries constrained)**, **Audit log (partitioned read)** — each box is split into a harbor-colored half and a beacon-colored half with a bold wall between them, labeled "no cross-partition reads." A fourth arrow from the gate goes to **submit_as → Action Executor (Ch 10)**, labeled "order.tenant_id == session.tenant_id, else TenantMismatch." Red dashed arrows show the three defeated attacks: "forged token → bad signature," "edited scopes → bad signature," "harbor session + beacon order → TenantMismatch," each terminating at the gate or the binding with a bold "✕ STOP" marker. Caption beneath: "The process is shared; the authority is not. Every arrow into shared state passes the gate." Style: clean technical architecture diagram, two tenant colors (blue/orange) plus neutral gray for the shared process, red for defeated attack paths, monospace labels.
